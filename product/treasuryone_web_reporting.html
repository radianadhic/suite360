Modul yang ada — dengan status yang jujur

18 grup navigasi · 185 item menu (203 baris navigasi) · 221 tabel + 4 partisi + 2 view di skema treasury (Flyway V1–V31). Legenda: ✅ jalur API + uji nyata · 🟡 skema & seed ada, logika/UI sebagian · ⚪ skema saja (roadmap).

🗂️

Master Data & Parameter

🟡 counterparty, book, SSI, holiday calendar, securities, currencies — tabel + seed; CRUD lewat API konfigurasi + persetujuan.

💱

Dealing Center

🟡 FX / money market / fixed income / derivatives: skema deal + generator komponen settlement & jurnal beruji; smart ticket UI memakai data contoh lokal.

🎯

Risk & Control

✅ LimitEngine (PASS <80% / WARN / BLOCK >100, mismatch mata uang = BLOCK), pre-deal check value-date & status counterparty, utilisasi dihitung set-based (flat di 3.000+ open deal).

🌪️

Skenario Risiko & VaR

✅ definisi skenario tekanan berfour-eyes; VaR delta-normal plus Expected Shortfall parametrik (es_amount + es_method di tiap run) (draf → ajukan → disetujui orang kedua → retire), dijalankan di atas valuation_results; VaR delta-normal dari sigma/korelasi + limit dengan bukti pelanggaran di control_violation_log. Yang tanpa model dilaporkan UNMODELED/UNSUPPORTED, bukan dianggap nol.

📐

Valuasi

✅ ACT/360 accrued, FX mark-to-market, bond price→clean; NO_PRICE dikembalikan null — tidak pernah menebak harga.

🧾

Finance & Accounting

🟡 JournalEngine (whitelist variabel, DR=CR per mata uang), aturan jurnal 9 produk, posting idempoten, rekonsiliasi sub-ledger↔GL; accrual/fee/tax masih roadmap.

🔁

Rekonsiliasi Nostro

✅ tier-1 exact 100 · tier-2 fuzzy ±2 hari (skor 80−5/hari, strip prefiks FT/RTGS/BI/TT/SES/SSS) · tier-3 kandidat amount-only TIDAK auto-applied; break idempoten.

🌐

Kanal Pembayaran

🟡 SWIFT .fin, BI-RTGS/SSSS .txt, FAST .xml, core-banking GL-*.csv — generator file ke direktori yang disepakati + integration_file_log; layout final & ACK inbound menunggu sertifikasi BI/bank.

🏛️

Regulatory Hub

🟡 Antasena (TPU01/TSD01/TRS01…), OBOX, NOP, LHBU, PDN: struktur, aturan & governance terpasang; perhitungan bentuk laporan tertentu belum lengkap.

☪️

Treasury Syariah

🟡 akad, DPS approval, wadiah/mudarabah, nisbah, zakat sebagai modul (bukan add-on) — skema + alur, logika sebagian.

📊

Report Designer & Viewer

✅ drag-and-drop — lihat blok di bawah.

🧩

Extension Studio

✅ form builder drag-drop (JSON Schema), registry menu/modul, modeler BPMN 2.0 — semua lewat alur persetujuan 4-eyes.

🛡️

Tata Kelola & Audit

✅ maker-checker — termasuk aktivasi master data (calon → ajukan → disetujui orang kedua, V31) — matriks wewenang Flowable, hash payload anti-drift, audit_log berantai-hash SHA-256 dengan trigger yang menolak UPDATE/DELETE, verifikasi lewat GET /api/v1/audit/chain/verify + ekspor bukti ter-sign ECDSA utk auditor luar, konfigurasi berversi + config_effective_state.

⏱️

Batch & Penjadwalan

✅ EOD chain (freeze → valuasi → jurnal → nostro) dengan ledger eod_task_run, retry terukur; penjadwal report CRUD + sewa pemimpin (scheduler_lease) sehingga aman di N instance.

🧊

Operasi Data

✅ kapasitas diterapkan dengan guard terukur (V28): autovacuum + fillfactor pada deals/journal_*, BRIN hanya bila volume & korelasi membenarkan (kalau ditolak, angkanya masuk capacity_action_log), report_runs dipartisi RANGE(run_at) karena FK masuk = 0; retensi arsip (V27) & pembersihan ACT_HI_* tetap default-mati. pemangkasan jejak lama = DETACH PARTITION (data tetap terbaca di tabel *_detached_*, bukan DELETE); deals sengaja TIDAK dipartisi — 25 FK masuk.

📋

Task Station (antrean kerja)

✅ klaim tunggal, unclaim kembali ke pool kelompok, delegasi ke identitas aktif dengan jejak delegated_by lalu Kembalikan (PENDING→RESOLVED), complete/reopen ber-peran; tombol yang dirender = aksi yang diterima server (actions[] dari kebijakan), setiap aksi menulis history + audit; saringan antrean dibaca dari task_filter (USER/GROUP/ALL, filter=NONE utk seluruh pool).

Status tiap kartu diambil dari brosur kanonik (marketing/TREASURYONE_MARKETING.html) yang sendiri dibangkitkan dari hasil ukur — halaman ini tidak menambah atau mengurangi klaim.

  • Regulator native: Antasena, OBOX, NOP, PDN, LHBU, PSAK 71 & 112.
  • Risiko pasar terhitung: skenario tekanan (kurva · FX · ekuitas) di atas ledger valuasi, VaR delta-normal dengan limit; yang tanpa model dilaporkan UNMODELED, bukan nol.
  • Terbuka & terukur: REST API + kanal berbasis file; 298 uji otomasi hijau di PostgreSQL 16.

Kenapa TreasuryOne

  • Audit di atas estetika. Setiap angka di halaman ini bisa ditelusuri ke kode, uji, dan artefak verifikasi.
  • Lokal sampai kolom. Kalender libur BI, IDR, format file kanal, pelaporan OJK/BI, UI & dokumen Indonesia.

  • Angka risiko ada rumusnya. VaR/skenario diuji sebagai unit murni dan siklus layar penuh; belum ada greeks/CS01/Expected Shortfall — dan itu kami tulis.
